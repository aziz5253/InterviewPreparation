Dependency Injection
Dependency Injection (DI) is a design pattern used in software development to achieve loose coupling between classes.

Instead of a class creating its own dependencies, those dependencies are provided (injected) from outside.
Dependency Injection is the process of supplying the required objects (dependencies) to a class instead of the class creating them itself.

✅ Reduces tight coupling
✅ Improves code reusability
✅ Easier unit testing (mock dependencies)
✅ Better maintainability and scalability

Sequential access ❌ (no random access like array)


✅ When to Use Linked List (Real Scenarios)

🟢 Scenario 1: Frequent Insertions/Deletions
👉 Example: Music Playlist App
Add song → Remove song → Reorder songs

Why Linked List?

Insert/delete easily without shifting elements
Just update pointer

✅ Use Linked List when:

Data frequently changes in middle


🟢 Scenario 2: Implementing Queue or Stack
👉 Example: Call Center Queue

Calls come in → added to queue
Calls handled → removed

✅ Linked List helps:

Fast add/remove operations


🟢 Scenario 3: Undo/Redo Feature
👉 Example: Text Editor (MS Word)
Action1 -> Action2 -> Action3


Undo → move backward
Redo → move forward

👉 Uses Doubly Linked List

🟢 Scenario 4: Memory efficient growth
👉 When size is unknown:

Streaming data
Real-time logs


❌ When NOT to Use Linked List

Need fast search ❌
Need index-based access ❌
