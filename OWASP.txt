OWASP Top 10 (2021) — Senior Java Perspective
1. Broken Access Control
What it means

Users can access resources or actions they should not.

Common Java/Spring Issues
Missing authorization annotations
Insecure REST endpoints
IDOR (Insecure Direct Object References)
Role bypasses
Admin endpoints exposed
Vulnerable Example
@GetMapping("/user/{id}")
public User getUser(@PathVariable Long id) {
    return userRepository.findById(id).get();
}

Problem:
Any authenticated user can access any user's data.

@GetMapping("/user/{id}")
public User getUser(@PathVariable Long id,
                    Authentication auth) {

    User user = userRepository.findById(id).orElseThrow();

    if (!user.getEmail().equals(auth.getName())) {
        throw new AccessDeniedException("Forbidden");
    }

    return user;
}


@PreAuthorize("hasRole('ADMIN')")
@GetMapping("/admin")
public String adminEndpoint() { return "admin"; }
Use RBAC / ABAC
Validate authorization on backend only
Avoid relying on frontend checks
Use Spring Security method-level security

2. Cryptographic Failures

(Previously "Sensitive Data Exposure")

String password = "plainText";

BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
String hash = encoder.encode(password);	

Risks
Weak encryption
Hardcoded secrets
Plaintext passwords
Weak TLS config
Password Storage
WRONG
String password = "plainText";
CORRECT
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
String hash = encoder.encode(password);
Senior-Level Practices
Use BCrypt/Argon2
Use HTTPS everywhere
Rotate secrets
Store secrets in Vault/KMS
Disable weak ciphers
Encrypt PII data at rest

3. Injection

One of the most critical categories for Java developers.

SQL Injection
Vulnerable Code
String sql = "SELECT * FROM users WHERE name = '" + name + "'";

Attack:

' OR '1'='1
Secure Code
PreparedStatement stmt =
 connection.prepareStatement(
   "SELECT * FROM users WHERE name = ?"
 );

stmt.setString(1, name);
ORM Doesn't Fully Save You

Even with JPA/Hibernate:

Vulnerable
String q = "from User where name='" + name + "'";
Secure
Query q = entityManager.createQuery(
    "from User where name=:name"
);

q.setParameter("name", name);
Other Injection Types
NoSQL Injection
LDAP Injection
OS Command Injection
XPath Injection
Command Injection Example
BAD
Runtime.getRuntime().exec("ping " + host);
GOOD
ProcessBuilder pb = new ProcessBuilder("ping", host);

Senior Developer Security Mindset

A senior Java developer should think:

"How can this fail securely?"
"What if this input is malicious?"
"What happens if authentication breaks?"
"Can this service be abused?"
"How do we detect attacks?"
"How do we reduce blast radius?"

That mindset is what separates secure enterprise developers from developers who only implement features.
